Telelogs can now reach your logs through Telelog Cloud: a small collector runs next to Docker or Kubernetes and connects out, so nothing on your machines listens for connections. The app also keeps a list of servers you switch between.

## telelog-collector

- Sends one machine's Docker containers, or a whole Kubernetes cluster's pods, to Telelog Cloud over one outbound connection. The desktop app tails them live through the cloud, and Pro workspaces keep them as stored logs.
- Enroll it once with the token and gateway from your dashboard's **Add a collector**. It keeps its id and key in a state file, so restarts need neither again. A collector with a saved state ignores the token, which suits containers where it's always set.
- Stops cleanly on SIGTERM from Docker or Kubernetes.
- `DOCKER_HOST` can now name a `tcp://` or `http://` address, for a daemon or a read-only socket proxy, in both the collector and the server.

### Install

```sh
# Docker: one container next to the Docker daemon
docker run -d --name telelog-collector --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock:ro -v telelog-collector:/state \
  ghcr.io/tolaniverse/telelog-collector --enroll <token> --gateway <gateway>

# Kubernetes: one collector per cluster, reading pods and their logs through the API
helm install telelog-collector oci://ghcr.io/tolaniverse/charts/telelog-collector \
  --namespace telelogs --create-namespace --set enrollToken=<token> --set gateway=<gateway>

# Linux or macOS: the binary, checked against SHA256SUMS
curl -fsSL https://raw.githubusercontent.com/tolaniverse/telelogs/main/install-collector.sh | sh
```

**About the Docker socket.** To read container logs, the Docker collector (and `telelog-server`) is given
the host's Docker socket. `:ro` only stops the socket file from being replaced; it doesn't limit the
requests sent through it, and anything that can reach that socket can start containers and mount the
host's disks, which is the same as root on the machine. The collector itself only lists containers,
watches events and reads logs. If you'd rather enforce that, put a socket proxy that allows only those
reads in between, such as `tecnativa/docker-socket-proxy` with `CONTAINERS=1 EVENTS=1 POST=0`, and point
the collector at it with `-e DOCKER_HOST=tcp://<proxy>:2375` instead of mounting the socket. The
Kubernetes chart doesn't use the Docker socket: it reads pods and logs through the API with a
read-only role.

The Helm chart grants read access to pods and their logs only, across the cluster or in the namespaces you list (`--set 'namespaces={shop,payments}'`), keeps the collector's identity on a small persistent volume, and runs as a non-root user with a read-only filesystem.

## In the app

- **Saved servers.** Add servers with a name, address, token and CA certificate, test them before saving, and switch between them from the sidebar's server menu or the command palette. Tokens live in the macOS Keychain.
- **Telelog Cloud.** Choose **Sign in to Telelog Cloud**: the app shows a code and opens your browser to approve it. Your workspace's collectors then appear in the server menu and open like any server, with time ranges and the Storage screen answered from cloud storage on Pro.

## Also

- The bucket archive moved into its own crate, `telelog-archive` (Apache-2.0), which the server uses as before.
- The collector and archive crates are Apache-2.0; the server stays AGPL-3.0.

## Install

The server and app install as before: `ghcr.io/tolaniverse/telelog-server:0.4.0`, `cargo install --locked telelog-server telelogs`, or the archives and the macOS app below, checked against `SHA256SUMS`. The app isn't notarized yet; the first time, click **Open Anyway** in System Settings → Privacy & Security.
